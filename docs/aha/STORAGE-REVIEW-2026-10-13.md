## 结论

保留“内部应用数据、用户工作文件、主动收藏的资源库、外部项目”之间的边界。Aha 新建工作区采用 `Documents/Aha` 合理，增加 `Chats` 分类也合理；没有旧内容时不应产生迁移任务。

建议取消普通启动流程中的自动工作目录迁移，把旧会话继续使用原路径作为正常兼容行为。有真实内容且确需整理时，提供有预览、有范围的一次性导入/整理操作。当前通用设置中的大块“存储位置与迁移状态”应移除，保留模块内必要的文件位置操作。

现有迁移清单、已成功迁移项目的路径映射和文件访问校验不能随 UI 一起删除，避免破坏历史链接。

## 当前实现的问题

### 迁移的触发条件与状态不准确

`workspaceMigration/coordinator.ts` 先无条件创建三个目录，再枚举当前 Aha 数据库的项目，不是直接扫描旧 Synara 文件夹。共享 Home 被记为 blocked，导致没有实际搬迁内容也显示永久 0/1。重复启动和重试不会解决目录归属问题。

迁移流程在 `effectServer.ts` 启动链上被 await；大目录复制可能延长正常启动。为整理路径而自动切换已有会话 cwd，还涉及 provider 恢复、终端、worktree、自定义目录等，收益应足以支撑这一复杂度。

### 设置同时承载了三个不同任务

四个默认路径、资源库切换、一次性升级迁移被合成一张卡片。默认路径不等于旧会话实际路径；Chats 标签易被理解为聊天数据库。红色底层英文和缺乏前置条件的重试按钮不能指导用户处理问题。

### 精灵动画持久化更需要优先整理

编辑项目唯一的客户端存储在 IndexedDB，后端保存生成记录与资产。当前只删除本地项目不会同时清理服务端记录，持久引用也可能继续保留绘图资产。建议把编辑项目、动作及资产关联保存到后端持久存储，以 IndexedDB 做缓存；保留可携带的项目包导入导出，并实现跨绘图与精灵记录的引用清理。不要把所有中间生成内容自动塞进 Resource。

### 仍有上游命名的路径分支

`scratchWorkspaces.ts` 的 macOS scratch 根目录仍为 `~/Library/Caches/synara`；`provider/cursorSkillsDiscovery.ts` 仍指向 `~/.synara`。这说明存储规则尚未完全归一。应区分有意兼容读取和 Aha 自己的写入目录，集中路径定义；不能把协议名、锁名、项目内兼容标记一并机械改名。

## 建议的产品与迁移策略

### 新数据

保持当前 Aha 应用根目录和 Electron profile，避免新增一轮无必要迁移。用户工作文件沿用 `Documents/Aha/{Chats,Studio,Groups}`，首次实际使用时创建。Resource 保持独立素材库，自选库优先。

### 旧数据

1. 原有会话默认继续使用其真实路径；主目录和外部代码项目不进入自动搬迁队列。
2. 只有存在明确归属、实际内容和明确需求时，才规划一次性文件整理。先显示源、目标、文件量和关联会话，再进行复制、校验、备份与路径更新。
3. 空目录及逐字一致的初始化模板不构成需要用户处理的迁移任务；自定义说明文件仍是用户内容。
4. 若用户要从 Synara 导入聊天、Studio 或 Group，先设计完整的应用数据导入流程；单独复制 Documents 目录无法恢复记录与关系。
5. 已成功迁移的项目保持新路径；旧文件、映射与迁移记录保留。取消新自动迁移不能回滚已有成果。
6. 旧 Studio 本次只发现空脚手架，无需为它搬作品。后续如要清理，需先确认应用中的路径引用，不自动删除。

### 设置入口

| 信息或操作                             | 建议位置                                     |
| -------------------------------------- | -------------------------------------------- |
| 资源库位置、切换资源库、在访达中显示   | 资源中心页面内；切换入口已有时无需在通用重复 |
| 当前聊天工作文件夹                     | 会话内的文件/环境面板，显示该会话真实路径    |
| Studio / Group 工作文件夹              | 对应模块的设置或打开文件夹操作               |
| 内部数据目录、日志、诊断信息           | 高级/故障排查，按需展开                      |
| 绘图导出、精灵项目包导出               | 各自工作台                                   |
| 旧版导入/文件整理                      | 独立一次性流程，有真实候选内容时才提示       |
| 常驻迁移进度、无效重试、数据库备份路径 | 从通用设置主体移除                           |

短期不必为了四个路径新增完整“存储”一级设置。将来若实现完整备份、恢复、磁盘占用和安全缓存清理，再建设“数据与存储”，并按用户任务组织内容。

1. 移除通用设置里的迁移大卡片，保留资源中心自身的目录操作；保留已成功迁移的历史链接解析。
