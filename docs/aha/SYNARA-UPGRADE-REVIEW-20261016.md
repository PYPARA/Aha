# Synara 升级合并评估 — 2026-10-16

结论：**值得升级，建议以 Synara v1.0.5 正式标签为基线，完成 Aha 兼容整合后再验收。** 收益主要是长对话性能、会话生命周期保护、浏览器状态与焦点，以及正式开放的聊天内联可视化。迁移谱系与聊天界面需要人工整合，不适合直接把上游文件覆盖到当前目录。

本次只做版本核实、源码比较与临时仓库中的合并模拟。没有合并到 Aha 分支，没有改动应用源码、数据库或 release 产物，也没有生成安装包。本文是本次评估的新增文件。

## 必须处理的兼容问题

### 1. 数据库迁移 135 撞号

Aha 已有：

- `135_ImageGeneration`：绘图库。
- `136_ImageEditDocuments`：画板编辑文档。
- 已知旧 Aha `132_ImageGeneration` 到现有谱系的兼容别名。

上游在 v1.0.4 新增了 `135_ProjectionMessageTurnActivityIndex`，v1.0.5 继续使用该编号。该迁移为 `projection_thread_messages(thread_id, turn_id, updated_at)` 创建幂等索引。

`apps/server/src/persistence/Migrations.ts` 的 import 和注册项均发生明确文本冲突。直接选上游会丢掉 Aha 的绘图迁移注册；直接选本地会漏掉上游索引；简单同时保留两个 135 又会造成编号和谱系问题。

建议优先保留已落地的 Aha 135/136 身份，把上游这项幂等索引注册为新的本地迁移，并为原生 Synara 135 建立经过审查的谱系映射。正式实现仍需以现有迁移校验和备份规则为准，不能只改文件名或 tracker 数字。原 Aha 132 兼容路径也必须继续有效。

最低验收矩阵：新库、旧 Aha 132 绘图库、当前 Aha 135/136 库、原生 Synara 134/135 库、重复启动幂等、未知/混合谱系拒绝、绘图七类记录及画板编辑文档保留、升级备份计划正确。

### 2. 聊天、精灵和皮肤共用界面的整合

含当前工作区的 1.0.5 模拟结果为：9 个 content 冲突、67 个 modify/delete 冲突、1 个 file-location 冲突，共 77 条路径。9 个 content 冲突分别是：

- `AGENTS.md`。
- `apps/server/src/persistence/Migrations.test.ts`。
- `apps/server/src/persistence/Migrations.ts`。
- `apps/web/src/components/ChatView.browser.tsx`。
- `apps/web/src/components/ChatView.tsx`。
- `apps/web/src/components/Sidebar.tsx`。
- `apps/web/src/components/chat/ChatComposerFooter.tsx`。
- `apps/web/src/routes/_chat.settings.tsx`。
- `bun.lock`。

核心实现冲突集中在迁移注册与四个界面文件，另需处理锁文件。大部分其余冲突来自 Aha 先前删除、上游又修改的测试或文档，不等于 77 个业务模块都需重写；也不应为了消除冲突直接丢掉新增修复对应的回归测试。

已经检查的具体合并点：

- `ChatView` 同一位置新增了上游 provider handoff 状态与 Aha 的 `spritePlanEntries`，需要同时保留。输入提示文案需要保持 Aha 品牌和翻译。
- 新输入框 footer 的 `row` 布局状态必须与 `useAhaTranslation` 并存；侧栏排序组件的新 props 也要与翻译适配合并。
- 设置页的 `ImageProvidersSettingsPanel` 与 `McpConnectorsSettingsPanel` 需要各自保留，并服从原有功能门控。
- 自动合并结果保留了 Aha composer 区域和 `AhaBackgroundLayer`，但上游单行输入框、浮动胶囊及 ASCII 空白页改变了实际布局；需要验证五区皮肤、不透明底色、弹层、窄屏和嵌入式聊天。
- `MessagesTimeline.logic.ts`、`MessagesTimeline.tsx`、`useChatTurnExecution.ts` 和精灵 prompt 注入虽然自动合并成功，仍共用折叠、回复边界、卡片渲染和发送失败恢复路径。已看到精灵卡片逻辑与内联可视化代码同时保留，尚未运行合并后的行为测试。
- 自动合并保留了 Aha 的 `aha-next:` 协议识别和 production 功能门控；没有发现必须直接改写 Aha 皮肤目录、绘图引擎、精灵引擎或资源中心模块的上游改动。
- contracts 新增了内联可视化与 Connectors RPC，必须继续验证现有拆分 RPC group 的声明生成，防止再次出现类型声明规模问题。

### 3. 依赖与维护范围

上游 1.0.3 到 1.0.5 没有改动根 `package.json` 的框架与工具链版本，也没有升级 Electron；服务端主要新增 `@modelcontextprotocol/sdk@1.29.0`。因此主要成本在业务行为和数据谱系，依赖迁移本身较轻。

继续保留 Aha 的安装标识、协议、数据目录、中文翻译、默认与自定义皮肤、绘图/精灵/资源入口，以及本仓库 AGENTS 打包规则。上游文档和测试的恢复范围逐项判断。

## 正式版之后的候选修复

main 比 v1.0.5 又多了 10 个提交；它们也不在 v1.0.6-beta.1 中。以下三组值得在正式版整合后优先单独评估：

1. [#1945 长历史查询与热点路径优化](https://github.com/Emanuele-web04/synara/pull/1945)，`ad395418f`。处理审批/输入请求和任务快照重复扫描，减少事件处理过程读取完整历史。上游记录了大量活动下的合成基准改善，但不能直接作为 Aha 实测数据。涉及 ProviderCommandReactor，与 Aha 精灵上下文注入同文件，需额外检查。
2. [#1946 限制并发会话造成的刷新风暴](https://github.com/Emanuele-web04/synara/pull/1946)，`f81faa2f4`。流仍在正常交付时减少重复 replay，按 checkout 节流 Git 和文件刷新，并移除容易误报的 busy 浮层。上游 A/B 记录约 596 → 158 RPC/分钟；仍需验证断线、丢事件、最终状态和精灵文件更新不被延后遗漏。
3. [#1947 RPC 客户端排队](https://github.com/Emanuele-web04/synara/pull/1947)，`1c72baef4`。把高峰期请求先留在客户端队列，减少拒绝与反复重试。涉及共享请求分类、服务端 admission 和 Web transport，宜在 #1946 之后按完整依赖整合，覆盖超时、取消、断线与未确定发送状态。

main 最新几次 Claude effort picker 改动仍在连续调整界面行为，这进一步支持以固定正式标签先收敛整合范围。

## 建议执行顺序与验收边界

1. 保存当前 Aha 工作为可回退检查点，再在独立分支/工作区整合固定的 v1.0.5 提交。
2. 先解决迁移谱系及数据保留，再合并聊天页、精灵计划、输入框、翻译、侧栏和设置。
3. 更新必要的上游测试与锁文件，完成 contracts 声明、七个工作区类型检查、受影响服务/逻辑/浏览器测试和桌面完整构建。
4. 使用独立数据目录验证旧 Aha 升级、绘图/精灵/资源持久化、计划卡片历史与焦点跳转、附件发送失败恢复、长聊天滚动、内联可视化和浏览器状态；验证 production 构建的 Connectors 门控。
5. 正式版整合通过后，再评估上述 main 性能修复；打包、替换 release 或推送按后续具体请求执行。

评估定性：**收益高，整合成本中等偏高；值得安排一次正式升级。** 数据库编号冲突是明确阻断项，但存在可审查的兼容方案；当前没有发现必须放弃 Aha 绘图、精灵、资源中心或皮肤定制才能升级的架构冲突。

验证限制：本次没有消解全部冲突、没有运行合并后的类型检查/测试/构建、没有读取或迁移用户数据库，也没有进行真实 provider 或安装包升级验证。临时 merge-tree 结果用于识别整合范围，不能作为可运行版本交付。
