# Aha 用户文件目录与首次升级迁移

默认目录是系统文稿目录下的 `Aha/Resource`、`Aha/Chats`、`Aha/Studio`、`Aha/Groups`。Electron 将系统文稿路径通过 `AHA_DOCUMENTS_DIR` 传给服务端，独立服务端回退到用户主目录下的 Documents。目录由共享的 `ahaUserDirectories` 定义。

资源中心只在没有已保存配置时自动初始化默认库。已有自选资源库和暂时离线的库保持原配置。

## 工作目录迁移

服务端在数据库可用、孤立旧任务状态恢复完成之后，在 provider 和定时任务恢复前运行迁移协调器。根据当前 Aha 数据库内的项目类型及路径识别旧 `Documents/Synara` 下的托管聊天、Studio、Groups 目录；未登记文件和普通代码项目不迁移。迁移不扫描、修改或导入 Synara 的数据库。

流程是逐项目复制、逐文件哈希校验、数据库一致快照备份、原子提交项目和会话路径事件。使用持久化清单保存进度与路径映射，重启可继续。原文件永远保留；成功迁移后不会重复复制旧目录里的后续修改。

同名相同内容复用。同名不同内容或文件类型冲突会阻止整个项目切换，设置页面列出冲突，原会话继续使用旧路径。磁盘错误、源文件变化、外部符号链接、嵌套项目归属和 Git worktree 引用同样保留原路径并报告。内部相对符号链接按链接复制，不遍历目标。

旧版共享 Home 容器可能包含另一款应用或用户的其他文件，因此不会复制整个主目录或整个 Synara 根目录。可独立确认归属的聊天项目会迁移；不能确认归属的容器会保留原路径并出现在待处理列表中。

迁移保留项目 ID、会话 ID 和模型原生恢复标识。Codex 和 Claude 使用已有的 cwd 变更恢复流程；其他已有原生恢复状态的 provider 暂停迁移，避免静默重建上下文。活跃 turn 或后台 provider 工作不会被迁移；空闲旧 runtime 只停止进程，保留恢复状态。切换前关闭该项目的旧终端，不删除历史。自定义 Group libraryPath 和 userdata 内的默认 Group library 不迁移。

## 历史链接

原消息和事件文本不做字符串替换。只有当当前工作目录属于已迁移项目的新位置时，旧目录内的绝对图片和文件链接才映射到新位置。普通鉴权、文件授权和真实路径边界检查仍然生效。服务端图片访问也提供同样的兼容映射。

## 运维与重试

设置 → 常规 → 存储位置与迁移状态，显示四个目录、迁移项、冲突、进度与数据库备份路径，可在 Finder 中显示目录或重试失败项。

- 迁移清单：`userdata/aha-workspace-migration-v1.json`。
- 一致数据库备份：`userdata/workspace-migration-backups/`，每次实际切换的一轮迁移前生成。
- `GET /api/storage/migration` 返回状态和已生效路径映射。
- `POST /api/storage/migration/retry` 启动一次后台重试；不接受调用方指定路径或项目范围。接口沿用应用认证和 Origin 规则。
- UI 在迁移中每秒刷新状态，完成后降低查询频率。

绘图、附件、配置、凭据、日志和 Electron 数据位置不变。旧目录不自动清理、不替换成符号链接。需要退回旧版时先退出 App，并保留迁移清单、备份和两侧文件；不能简单把正在运行的 SQLite 文件替换掉。

## 测试

复制测试使用临时目录，涵盖权限、隐藏文件、冲突、中断恢复、源变更、符号链接与 ENOSPC。事件测试和真实 SQL 集成测试验证项目、线程与 provider runtime 路径一起提交，重放事件保留新路径与会话标识。浏览器测试验证目录显示、冲突提示、重试与进度。
