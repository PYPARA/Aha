# Aha「3D 生成」功能方案

状态：**M3a 已实现**（M1a：Three.js + SDF 参考驱动迭代闭环；M1b：Blender 建模路线和骨架数据；M2：优化、烘焙、LOD、碰撞体和多格式导出；M3a：参考图投影贴图和程序材质预设。使用说明见 [3D 生成](../../guides/GEN3D.md)，维护约束见 [3D 生成维护](../../development/GEN3D.md)）；M3b（平铺材质与贴花、局部改贴图）及之后仍是方案。M0 技术验证结论见第 10 节。日期：2026-11-03（同日修订：在没有外部 3D 生成渠道的前提下，首版改用内置 AI 建模）。本文是待评审方案，不代表已交付的行为。已有的 [3D 工坊](../3d-workshop/PRODUCT_SPEC.md)保持现状，本方案不修改它的行为、数据或工具接口。

## 1. 定位

参照 Tripo 这类生成式 3D 工作台，新增独立的主导航功能「3D 生成」（暂定名，路由 `/gen3d`，导航 ID `gen3d`，默认放在 3D 工坊之后）。

目前没有可用的 3D 生成渠道，所以首版的几何**全部由聊天模型通过 Three.js 或 Blender 构建**。这和 3D 工坊用的是同一类底层能力。两者的区别在于，3D 生成把 Tripo 的整套流程搬过来：参考驱动、自动比对迭代、有机建模、贴图投影、烘焙、绑定、多格式导出。外部 3D 生成渠道作为第二种生成来源保留接口，在 M5 接入，后处理管线和这一版共用。

|          | 3D 工坊（现有）                  | 3D 生成（本方案）                                                             |
| -------- | -------------------------------- | ----------------------------------------------------------------------------- |
| 工作方式 | 对话式建模，一问一答             | 参考图 → 三视图蓝图 → 建模 → 渲染比对 → 自动迭代                              |
| 建模表示 | Three.js 程序化 / Blender Python | 同上，另加 SDF 隐式建模（有机形体）、骨架蒙皮建模（角色和生物）、程序表面细节 |
| 质量判断 | 模型读文字报告                   | 模型看多角度渲染图，并读和参考图比对的**量化评分**                            |
| 资产化   | PBR 参数、本地贴图、GLB/Godot    | 自动 UV、高模烘焙到低模、参考图投影贴图、LOD、碰撞体、骨骼和动画、多格式导出  |

两者只通过标准文件衔接：3D 生成的 GLB 入库到资源中心后，可以用 3D 工坊**已有的**导入功能继续编辑。本方案不在工坊里新增入口。两者能力有重叠，是否合并在 3D 生成稳定后另行评估，不在本方案范围内。

### 能达到什么程度（预期，M0 验证）

| 资产类型                                           | 内置 AI 建模的预期                                                              |
| -------------------------------------------------- | ------------------------------------------------------------------------------- |
| 硬表面：道具、武器、家具、建筑件、载具             | **可用的游戏资产**。拓扑和部件比扫描式生成更干净，形体精度取决于参考图          |
| 风格化有机：Q 版或低多边形角色、玩具、简单生物     | **中等**。SDF 和骨架蒙皮能做出可信的体块，五官、手指等细节偏简化                |
| 写实人物、复杂有机（面部、衣褶、毛发）、照片级还原 | **做不到**。需要外部 3D 生成渠道（M5）                                          |
| 贴图                                               | 程序 PBR 材质质量稳定；参考图投影在正面效果好，侧面、顶部和遮挡处要用程序材质补 |

### 目标

1. 文字或参考图生成带 PBR 材质和 UV 的模型，可以出多个候选，挑选后继续。
2. 参考驱动的自动迭代：每轮渲染和参考图比对，评分和差异图交给模型修改，直到达标或用完轮数。
3. Tripo 式后处理：检查与归一化 → 减面 → UV → 高模烘焙到低模 → LOD/碰撞体 → 多格式导出。
4. 贴图投影、局部改贴图、部件、绑定与动画、风格化。
5. 每一步生成不可变版本，可以回退、对比和分叉；所有消耗（模型轮次、生图）都需要用户授权，并且可以追溯。

### 非目标（首版）

- 不接外部 3D 生成服务，也不运行本地 3D 生成模型（均在 M5）。
- 不做完整的 DCC 编辑器（雕刻、手动拓扑、手绘骨骼）。
- 不做场景或关卡生成，只做单个资产。

## 2. 能力来源

| 能力                       | 用途                                                                                      | 现状                                                                                                      |
| -------------------------- | ----------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------- |
| 聊天模型（如 GPT-6.1 Sol） | 理解需求、规划部件、写建模代码、看渲染图、根据评分修改、命名部件、决定后处理参数          | 已有。Agent Gateway 工具结果已支持返回图片（浏览器、精灵、批量生图工具都在用）                            |
| 生图渠道（可选）           | 概念图、正交三视图、平铺材质、局部重绘                                                    | 已有生图渠道和参考图编辑。**没配置时功能降级但不阻塞**：用用户上传的参考图，或者只用文字                  |
| Three.js 执行环境          | 程序化建模、SDF 网格化、渲染比对、GLB 导出                                                | 复用 3D 工坊的沙箱机制（专用 BrowserWindow + Worker、无网络和文件访问），但使用 3D 生成自己的入口和辅助库 |
| Blender                    | AI 建模（修改器、Skin、Metaball、体素重建）、固定后处理脚本（UV、烘焙、减面、导出、绑定） | 复用工坊的 Blender 检测和运行环境；和工坊共用一个全局 Blender 任务锁                                      |
| 查看与校验                 | 查看器、glTF Validator、哈希与容量检查、缩略图、资源中心入库                              | 已有，以引用方式复用                                                                                      |

### 两种 Blender 执行方式

- **AI 建模代码**：沿用工坊的 MCP 专用 GUI 实例，以及源码的 AST 发布规则（禁止文件操作、发布路径、动态属性访问等）。上游插件不支持 `-b` 模式，所以这部分必须用 GUI 实例。
- **固定后处理脚本**：Aha 自带的脚本，参数通过 JSON 传入，用 `blender -b --python <脚本> -- <参数>` 无界面运行，不经过 MCP，也不执行 AI 生成的 Python。

## 3. AI 建模路线（核心）

### 3.1 输入与参考

- 支持的输入：文字、1 张参考图、2–4 张多视图、资源中心的图片、批量生图结果。资源中心和批量生图的图片通过模块间传递队列 `queueResourceTransfer` 接收，新增 target `gen3d:<projectId>`。
- **概念图**（配置了生图渠道时）：模型把需求整理成适合建模的提示词（单个物体、纯色或透明背景、完整不裁切、光照均匀），用户确认后生成 2–4 张，再挑选一张。
- **三视图蓝图**：用生图生成**一张**左右排列正、侧、背三视图的参考图，然后自动按列切分，这样比例、底线和配色一致性最好（M0 实测）。也可以根据选定的概念图用参考图编辑生成。三视图必须展示给用户确认，可以重新生成或换成手工上传。侧视的朝向可能是镜像，评分时会自动匹配。
- **剪影提取**：从透明背景，或者把「与边框连通的近白像素」判为背景（封闭的浅色区域保留为前景），得到每个视图的剪影遮罩，再标出主体的包围框和地面线。三个视图共用一个比例，同时适配最高和最宽的视图。用户可以在界面上微调阈值和裁剪。
- 尺寸：用户填写目标尺寸（比如高 1.8 米），或者由模型根据物体类型提议，用户确认。
- 没有参考图时，跳过蓝图和评分，退化为纯文字建模加渲染图审阅（第 3.4 节的视觉部分仍然生效）。

### 3.2 建模表示

模型按资产类型选择表示方式，同一工程里可以混用（比如 SDF 身体加硬表面装备）：

| 表示             | 适合                         | Three.js 路线                                                                                                                         | Blender 路线                                                          |
| ---------------- | ---------------------------- | ------------------------------------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------- |
| 程序化硬表面     | 道具、建筑、载具             | 基本体、挤出、车削、曲线扫掠、CSG                                                                                                     | bmesh、Bevel / Boolean / Mirror / Array 修改器                        |
| **SDF 隐式建模** | 有机体块、圆润造型、融合形体 | Aha 提供的 SDF 辅助库：基本体（球、胶囊、圆角盒、圆锥、圆环）、平滑并集/差集/交集、变形，然后用 Surface Nets 或 Marching Cubes 网格化 | Metaball、Volume（Geometry Nodes 点转体积再转网格）、体素 Remesh 融合 |
| **骨架蒙皮建模** | 角色、生物、树木、触手       | 骨架图（节点 + 半径）→ 沿骨段生成扫掠体并做 SDF 平滑融合                                                                              | Skin 修改器 + Subdivision，从骨架图生成主体                           |
| 程序表面细节     | 磨损、纹理凹凸、铆钉、木纹   | 高度函数位移                                                                                                                          | Displace 修改器 + 程序纹理；高模细节最终烘焙成法线贴图                |

- SDF 辅助库作为 `buildModel({ THREE, SDF, params })` 的注入参数提供，保持「源码不能 import」的规则。网格化分辨率默认 128³，上限 256³，用窄带 Surface Nets 计算，并按块剔除不相交的基元（M0：12 个基元 256³ 约 0.8 秒；120 个基元不剔除时约 16 秒）。网格化后固定执行一次非流形清理，因为细小结构处会出现少量非流形边。
- **骨架图是一等数据**：骨架建模时保存节点、父子关系和半径（`skeleton.json`），后续自动绑定直接使用（见 3.8），不用事后猜关节位置。
- 输出约定沿用工坊：米制、Y 轴向上、轴心底部居中、命名部件、`MeshStandardMaterial` 或 Principled BSDF。

### 3.3 渲染与比对评分（免费，本地）

每次构建完成，可信 Three.js 层生成：

1. **对齐视图**：用和三视图相同的正交相机渲染剪影、深度和带材质的颜色图。纵向按**共同的物理比例**（用户确认的目标尺寸换算成像素/米）和地面线对齐，横向在小范围内搜索 IoU 最大的平移。不能按各自的包围盒缩放或居中，否则一处局部偏差（比如天线短了）会让整个剪影错位、到处误报（M0 已验证）。
2. **评分**：逐视图计算剪影 IoU、轮廓的倒角距离（按包围框归一化），以及高宽深比例偏差，最后给出总分（0–100）。
3. **差异图**：参考剪影和模型剪影叠加，多出的部分标橙、缺少的部分标蓝（明度也不同，不只靠色相区分），并标注偏差最大的几个区域（比如「左视图头部顶部缺 8%」）。
4. **自由视图**：3/4 视角、俯视和线框图，用来判断剪影看不出的问题（比如凹陷、朝向、比例）。

评分只说明轮廓和比例，不能代表风格和细节是否正确，所以界面和模型规则都要求同时看渲染图。

### 3.4 自动迭代

- 用户发起「生成」时设置**轮数上限**（默认 4，最多 10）。这一授权允许模型在上限内连续「构建 → 比对 → 修改」，不需要每轮确认。
- 每一轮都发布为候选版本，并记录分数，版本树里可以看到分数曲线。没有超过阈值的偏差区域、分数连续两轮没有提高、或者用完轮数时停止，然后由用户挑选。
- **停止条件不用固定的总分**：M0 中一个明显错误的候选（三处偏差）也得了 87 分。M0 用 5 类真实样本标定后，默认改为「最大偏差区域 < 2%」，同时要求分数连续两轮提高不足 1 分时停止。
- 每轮模型耗时约 3–10 分钟（M0 用 GPT-6.1 Sol 实测，第一轮最长），任务区必须显示当前轮次和已用时间，并可以随时取消。
- 用户可以随时暂停或停止；也可以在任意一轮的版本上手动「从这里继续」，并补充文字要求。
- 多候选：默认 1 条分支（单轮耗时较长），可选并行开 2–4 条独立的迭代分支（不同表示或不同解读），分支之间不共享上下文，但都受同一个轮数授权的约束。并行数受会话模型的并发限制。
- 模型轮次的消耗在任务区显示（轮数、耗时，provider 有用量数据时一并显示）。

### 3.5 GPT-6.1 Sol 等模型的使用前提

- 必须能在工具结果里接收图片。模型不支持时，`views` 只返回评分和文字描述，界面提示「当前模型无法查看渲染图，效果会下降」。
- 同一套流程不绑定具体模型，使用会话里已选的模型。M0 会用 GPT-6.1 Sol 和至少一个其他模型做对比，结论写回本文。

## 4. 资产化管线（本地，免费）

后处理与几何来源无关，M5 接入外部渠道后直接复用。

### 4.1 检查与归一化

- 统计：三角面、顶点、部件、材质、贴图尺寸与通道、包围盒、文件大小。
- 检测：非流形边、孔洞、游离碎片、法线翻转、退化面、重复顶点、缺 UV、UV 重叠和越界。
- 归一化：米制、Y 轴向上、底部居中、按目标尺寸缩放。
- 自动修复（固定脚本）：按距离合并顶点、删除碎片、补小孔、重算法线。修复结果生成新版本。

### 4.2 高模、低模与 LOD

- SDF 和程序细节产出的通常是高模（几万到几十万面）。固定脚本用 Decimate 或 QuadriFlow 生成目标面数的低模。
- 预设：主资产 20k、普通道具 5k、背景 1.5k、手机 800 三角面，也可以自定义。
- **烘焙**：Cycles「选中到活动」，把高模的法线（切线空间，OpenGL/DirectX 可选）、AO、颜色、粗糙度、金属度烘焙到低模，可设置笼框距离和边缘外扩像素。
- LOD1/2 从低模继续减面，共用同一套贴图；碰撞体可以选包围盒、凸包或 V-HACD 凸分解。

### 4.3 UV

- Blender Smart UV Project + 打包，按贴图尺寸设置外扩边距，可选按目标纹素密度缩放。程序化硬表面部件可以由模型指定接缝（标记 seam 后 Unwrap）。
- 查看器提供 UV 棋盘格和 UV 布局视图。
- 重新展开 UV 会让旧贴图失效，所以必须和烘焙或重新贴图一起执行。

### 4.4 贴图

| 方式           | 实现                                                                                                                                                                 | 依赖     |
| -------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------- | -------- |
| 程序 PBR 材质  | 模型写 Blender 材质节点（噪声、磨损、边缘高光、污渍、木纹、金属拉丝），按部件指定，最后烘焙成标准 PBR 贴图                                                           | 无       |
| **参考图投影** | 把选定的概念图和三视图按 3.3 的对齐相机投影到 UV，按法线和视线夹角加权混合；没有覆盖到的区域（遮挡、顶底面）用该部件的程序材质填充；颜色贴图之外的通道由程序材质给出 | 参考图   |
| 平铺材质与贴花 | 生图生成可平铺的颜色图和贴花，本地算法推出法线和粗糙度，再按部件或遮罩混合后烘焙                                                                                     | 生图渠道 |
| 局部改贴图     | 锁定视角 → 画遮罩 → 渲染该视角的颜色、法线和深度 → 生图局部重绘 → 投影回 UV → 羽化融合 → 新版本；遮罩外的像素不变                                                    | 生图渠道 |

- 几何是按剪影拟合的，所以投影贴图在正面对齐度可以接受。分数低于阈值（默认 75）时，界面提示投影可能错位，建议先继续迭代几何。
- 贴图规范沿用工坊约定：PNG，颜色贴图 sRGB，其余为线性；glTF 的粗糙度放 G 通道、金属度放 B 通道；单张最大 4096。

### 4.5 部件

- 程序化和骨架建模天然带命名部件。SDF 融合后的整体网格保留「部件 → 区域」的映射，按最近的 SDF 基元归属，可以按部件高亮、单独指定材质。
- 也可以按松散部件或材质分离，或者按用户画的遮罩切割。

### 4.6 绑定与动画

- **骨架建模的资产**：直接从 `skeleton.json` 生成骨骼（人形映射到标准骨骼命名，方便重定向），用 Blender 自动权重蒙皮，查看器显示骨骼和权重热力图，用户可以拖动关节后重新蒙皮。
- **其他资产**：模型根据正面和侧面渲染图提出关节位置（Rigify 元骨骼），用户在查看器里确认或调整后再蒙皮。
- 动画：固定脚本提供程序化循环（待机呼吸、行走、奔跑、攻击挥动，参数可调），道具动画（开盖、旋转、开门）由关键帧参数生成；模型可以写自定义关键帧，但只能在固定的动画 API 范围内。
- 导出 GLB/FBX 时包含骨骼和动画片段；3D 生成的查看器在自己的可信加载层播放动画，不放宽工坊 Worker 的限制。

### 4.7 风格化

本地算法：体素化（分辨率可配，可选沿用贴图颜色）、低多边形平面着色、积木风格（体素 + 凸点实例化）。输出都是新版本，可以继续走后处理。

### 4.8 导出与入库

- 格式：GLB（默认）、FBX、OBJ+MTL、USDZ、STL/3MF（3D 打印要求网格闭合，会做壁厚检查）。非 GLB 格式由 Blender 固定导出脚本生成。
- 引擎预设：通用、Godot、Unity（FBX，比例和轴向）、Unreal（FBX，Z 轴向上、单位厘米）。预设只决定格式和轴向参数。
- 导出内容：模型、LOD、碰撞体、外置贴图（按格式需要）、`thumbnail.png`、可选 `turntable.webp`、`asset.json`（来源、会话模型、提示词、参考图哈希、父版本链、评分、面数、贴图、骨骼和动画）、`validation.json`。
- 入库：资源中心新增 `ResourceOrigin.kind=gen3d`（projectId/versionId），复用持久化复制回执和失败重试；重试只复制已有产物。

## 5. AI 编排

新增 Agent Gateway 工具 `gen3d`：

- `get`：工程、版本树、当前版本的统计、问题和分数、参考与蓝图摘要、骨架。
- `views`：当前版本的对齐视图和差异图、3/4 视角、线框、UV 棋盘格，以图片返回；同时返回评分 JSON。
- `submit`：提交建模（mode 为 `threejs` 或 `blender`，以及源码、参数、父版本），或者提交后处理操作（固定操作类型加参数）。
- `status` / `report`：读取任务状态和真实报告。
- `proposeImages`：提出概念图、三视图、贴图类的生图请求，**用户确认后**才执行（沿用批量生图「方案 → 确认」的规则，因为生图会产生费用）。
- 每轮注入的规则：先 `get`；修改前先看 `views`；在授权的轮数内迭代，不能超出；不能根据代码或参数声称成功；保留没被要求修改的部件和稳定 ID；如实报告失败原因。
- 采用、导出、归档、删除只能在工作台操作。会话绑定、删除会话只解除绑定、活跃轮次校验，全部沿用现有机制。

## 6. 数据与执行

### 6.1 存储

工程数据放在 `Documents/Aha/Gen3D/<projectId>/`，跟随 Aha 的 Documents 配置。文件是数据真相，不新增数据库迁移：

```
project.json          工程清单、版本树、当前/采用指针、修订号、迭代授权
inputs/<id>/          参考图、概念图、三视图、剪影遮罩（引用生图资产时记录资产 ID）
operations/<id>.json  操作输入快照、来源（ai/fixed/provider）、参数、状态、轮次
versions/<id>/        model.glb、source（js 或 py）、skeleton.json、textures/、lod/、collision/、
                      views/（对齐视图与差异图）、score.json、report.json、thumbnail.png、可选 model.blend
```

- 版本不可变，目录不能覆盖。每个工程串行写入，修订号防止并发覆盖；requestId 加内容指纹实现幂等。
- 「当前版本」（AI 上下文和后续操作的默认父版本）和「采用版本」（导出和入库使用）分开管理。

### 6.2 执行与恢复

- 输入先落盘，执行并校验成功后再原子发布版本。失败保留源码、日志和上一个可用版本。
- 自动迭代的状态（授权轮数、已用轮数、停止原因）持久化。重启后**不自动继续迭代**，标为「已中断」，由用户点「继续」，从剩余授权轮数开始。
- 生图请求走现有引擎和确认回执；状态不明时按现有规则核实，不盲目重发。
- Three.js：单次执行 60 秒（SDF 网格化比工坊需要更多时间），源码 1 MiB，结果 200 MiB、200 万三角面（超过导出预算时提示先减面）。
- Blender：AI 代码单次调用 120 秒；固定脚本各自有超时（默认 10 分钟，烘焙可配）。取消只终止 Aha 自己保存的子进程句柄。和工坊共用全局 Blender 锁，排队时显示「等待 Blender」。
- 没有桌面宿主时（纯 Web），只能查看，不能构建。

## 7. 安全

- Three.js 源码只在沙箱 Worker 中执行（无 Node、网络和文件访问，CSP 只允许 `data:`/`blob:`），Worker 输出要先通过结构和容量校验，才能进入可信层。
- Blender AI 代码沿用 AST 发布规则和上游安全模式。专用实例只用于工程隔离，不是操作系统级沙箱，界面和文档要如实说明。固定脚本只接收经过 schema 校验的 JSON 参数。
- 导入的参考图只作为图片处理。生图结果沿用现有资产存储和引用保护。
- 所有发布的 GLB 都要求 glTF Validator 零错误、嵌入贴图能解码、没有外部 URI。

### M0 进展（2026-11-03，基本完成）

过程记录、样本和对比图在 `.tmp/gen3d/m0/`（本机忽略目录，见其中的 `RESULTS.md`）。

- **剪影评分**：人为偏差全部定位、没有误报。对齐要用共同的物理比例和平移搜索，侧视还要尝试镜像（3/5 的真实样本用了镜像）。
- **Blender 后台固定脚本**：
  - 已跑通：骨架 Skin 建模、自动权重、挥手动画、Decimate 到 5k、Smart UV、高模到低模烘焙法线和 AO。

  - 导出设置：开启切线，蒙皮网格放在根节点。
  - 导入 OBJ 后要先应用旋转。
- **真实参考图 + GPT-6.1 Sol**：
  - 参考图：5 类样本各用绘图渠道生成 1 张三视图，每张 17–26 秒。
  - 迭代：每个样本跑 3 轮，15 轮全部成功，没有执行命令。

  - Q 版骑士 85 → 88，小狐狸 89 → 92。
  - 单轮 4–14 分钟，输出 1.1–3.6 万 token。
- **参考图投影贴图**：
  - 硬表面三类的条纹、包边、锁、窗、门都对得上，接近可用。

### M1 实施计划（2026-11-03 开始）

- **M1a：Three.js + SDF 闭环**

  - 桌面宿主 `apps/desktop/src/gen3d/host.ts`：独立的本机 socket 和随机令牌。
  - 沙箱运行页 `gen3d-runtime.html`：Worker 里注入 `SDF` 辅助库（基本体、平滑布尔、窄带 Surface Nets），可信层负责归一化、统计、GLB、缩略图、对齐剪影和多角度渲染图。

  - `gen3d` 工具：get / views（返回图片）/ submit / status / report。
  - 工作台：首页、参考与版本、查看器（复用工坊查看器，不修改）、属性与 AI 助手、任务栏、导出 GLB、资源中心入库。
- **M1b：Blender 路线**（2026-11-04 已实现）
  - AI 写的 Blender Python 走工坊的 MCP 运行环境，共用全局锁；锁被占用时等待，不失败。

工坊只做必要的接入改动：绑定互斥检查要识别 3D 生成；资源中心新增来源类型。工坊自身的行为不变。

- 每个阶段都跑 `bun run typecheck`、`bun run build:desktop`，以及 3D 工坊的核心回归，确认工坊没有被影响。

## 12. 风险

| 风险                         | 应对                                                                        |
| ---------------------------- | --------------------------------------------------------------------------- |
| 模型建模能力不够，达不到预期 | M0 先用真实样本定预期；按资产类型提示适用范围；保留 M5 外部渠道             |
| 剪影评分高但看起来不对       | 评分只是辅助，必须结合渲染图审阅；用户随时可以停下手动指导                  |
| 三视图不一致导致评分误导     | 三视图必须经用户确认；允许单视图禁用评分或降低权重                          |
| 迭代消耗过多模型轮次         | 用户设定轮数上限；分数停滞时自动停止；任务区显示消耗                        |
| SDF 网格化耗时或面数过高     | 分辨率可配、窄带计算；高模交给减面和烘焙                                    |
| 投影贴图错位或有接缝         | 分数阈值提示；按法线加权混合；未覆盖区域用程序材质补；保留旧版本            |
| 和 3D 工坊重复               | 只通过 GLB 和资源中心衔接；抽取公共模块必须跑工坊回归；稳定后再评估是否合并 |
