# 精灵工作台制作与修帧

新项目按“角色 → 动作 → 导出”制作，默认插画、256×256动作画布。角色单图请求默认1024×1024；新动作方案跟随输出单帧与帧数：256×256、8帧、1×来源对应4列×2行、1024×512。角色图片、动作输出和请求模式独立。像素项目仍可选择64×64逻辑画布和4倍输出，旧项目不自动改写。工程主版本仍为v1/v2；后文描述当前源码行为，维护约束见[创作功能维护](../development/CREATIVE_WORKBENCHES.md)。

## 制作与修复

1. 上传角色图、选择已有素材，或点击“生成角色”进入右侧助手，描述需求并准备方案。打开入口只恢复当前目标，不创建方案、消息或任务；明确点击“开始生成”才提交。重复进入及刷新恢复同一目标草稿，不同动作保留独立草稿。调整背景、角色大小、位置和地面线，先预览，再点击“确认角色基准”。已有图片的预览和确认不创建绘图任务。
2. 在动作列表中设置描述、帧数、FPS 和循环方式，输入生成要求，准备动作生成计划。计划卡显示模型、基准、任务数和片段范围，确认后才提交绘图。没有可信价格信息时显示费用未知。
3. 每个图片任务最多生成 8 帧。不同动作默认最多同时执行 2 个任务，并受供应商并发设置限制。同一动作的后续片段等待前一片段通过几何检查，携带固定角色基准、前一片段最后两帧和本片段布局图。
4. 在动作页检查候选原图、切片、逐帧动画及完整动作，任务条负责定位。切片、背景和整体对齐通过“从原图重新处理 · 免费”或纠偏编辑器修复；这些操作保留原图，不创建绘图任务。姿势或角色画错时，修改方案或重新生成对应动作／片段，再通过计划卡确认。
5. 一个动作的全部片段就绪后才能统一“确认检查并采用”，不要求逐项勾选。采纳保留全局帧顺序、FPS、循环方式及片段来源。画布支持前后帧叠影、角色基准对照和地面线；帧偏移可以拖动、用方向键或数值输入修改。
6. 导出 PNG 序列、单动作图集或合并图集。图集由程序按动作、帧顺序组装，导出预览与实际资源使用同一套帧几何计算。“保存工程包”保存可编辑项目，“导出动画资源”输出 PNG 和动画元数据。

修改角色基准会创建新版本，使尚未确认的旧计划失效；既有动作及其原始基准快照保留。逻辑分辨率或画风变化需要重新确认基准。仅修改输出倍率时，已有逻辑母版可以直接重新导出。

## 从其他模块接收与导出入库

资源中心的「用于…→用于精灵」、批量结果的「用于精灵」和绘图历史的「用于精灵」都会让你选择已有精灵项目或「新建精灵项目」（先填写项目设置），图片加入该项目的图片素材，不会自动生成或改写动作。项目还没有角色基准时，会切到「角色」并预选第一张图，仍需检查后点击「确认角色基准」。无法解码或超出容量的图片会单独提示，不影响其他图片。

导出页的「加入资源中心」使用与「导出动画资源」相同的帧与图集，文件名加上项目名前缀（序列帧目录压平为文件名），`animation.json` 中的引用同步改写；选择资源库位置后逐个入库，来源记为本项目，可从资源详情回到项目。加入资源中心不记录为“上次导出”。

## 本次请求与参考图

供应商设置不再包含“精灵生成模型能力”。旧能力字段只用于兼容读取，不根据这些声明拦截新请求。模型是否接受参数以实际响应为准，失败保留原方案，不自动降级、换模型或收费重试。

每份生成方案仍可配置供应商、模型、生成尺寸、参考图片及用途、质量、格式、背景；动作另有帧数、FPS和循环。角色请求尺寸表示单张角色图，动作请求尺寸表示整张精灵表。技术参数可折叠但可直接查看和编辑。512等自定义请求按输入发送，不沿用普通尺寸控件的自动放大规则。

默认8帧仍为一次精灵表请求，联动模式下一张1024×512图中排布4×2个256来源格。超过8帧沿用分段制作，更改角色参考图或输出单帧尺寸不增加请求。切帧根据实际返回尺寸计算；请求与实际尺寸不一致仅提示，两者比例不同需要人工复核几何。

角色原图保留；插画确认时分别从原图派生高分辨率外观参考和小尺寸动作对齐图，并绑定同一基准修订。动作优先使用大图作外观参考，小图负责共同画布中的比例和落脚点。旧基准缺少新引用时继续使用既有参考，像素模式保持原采样规则。当前基准、基准历史及动作版本引用的素材不会被常规清理移除。

动作和物理图片行互相独立。`SpriteTaskLayout` 保存有效格子的动作 ID、全局帧号和坐标，同一映射用于提示词、布局参考图、分析、切片和编辑器。一个动作可以跨图片多行。

## 渲染与恢复约束

- 像素模式保存逻辑母版，使用最近邻归一化、硬透明边缘和整数倍输出；插画使用平滑缩放并保留半透明边缘。动作帧使用共享画布及变换，内容检测不逐帧缩放或居中，因此跳跃等有意位移得到保留。
- 切片保留原格子的坐标原点，修改裁切框不会自动把角色重新居中。超出画布的角色需要扩大画布、调整共同缩放或重新生成；后处理无法恢复原图已经缺失的身体部分。
- 色键抠图叠加已有 alpha，从保留的原图重新计算去色污染。透明模式发现不透明背景时显示问题，由用户调整处理。
- 无法解码、空帧、缺帧、切片越界和重叠阻止采纳。边界接触、重复、背景残留及片段／循环衔接风险以具体帧号展示，最终动作质量由人工检查。
- 确认先持久化已授权任务及 `prepared` 阶段，再提交。恢复时按幂等键关联持久化绘图任务；提交状态不确定时不盲目重发。处理失败保留付费原图；可识别的瞬时本地错误最多重试两次。
- 修帧编辑器保留至少100步撤销／重做，一次拖拽为一步，草稿保存在本地。分析使用独立修订号；并发冲突允许对比、将草稿另存为处理版本，或载入最新版本并保留撤销入口。
- v1 项目沿用旧帧像素及渲染行为。v2 项目、桌面存储及工程包保存规格、基准历史、逻辑母版和来源；工程包清除会话绑定，导入到另一数据环境后可以从包内素材重新确认角色。

## 失败重试与版本更新

生图失败时可从方案卡片或任务详情选择“重试失败任务”。先核对原参数和任务数，再明确确认提交；新请求可能再次计费。只重试失败且没有可用图片的任务，成功候选与历史尝试保留。渠道或参考图失效时修改方案后重试；提交状态不确定时先核实已有任务，避免重复请求。

切帧或背景处理失败使用免费重新处理或修帧入口，不重新生图。保存修正只产生处理版本；回到候选后核对并采用，已有动作更新前确认替换的帧、FPS与循环设置，并保留版本和撤销入口。

## 回归验证

固定图片和模拟绘图服务覆盖布局与帧顺序、片段依赖、幂等恢复、免费处理、角色版本、并发处理分叉、跳跃位移、混合 alpha、整数像素块、插画透明度和 v1/v2 兼容。浏览器用例覆盖角色确认、数值中间态、撤销草稿、工作台响应布局、拖图隔离、工程包往返及导出一致性。

真实生成验收应在加载本次源码的应用中，通过正常计划卡分别完成像素和插画项目，包含跳跃、一次免费处理修复和一次付费局部重生成。自动测试中的图像夹具不作为真实 AI 动作质量的验收证据。

## 统一修帧

候选、任务、素材与手工导入进入同一个编辑器。恢复顺序是未保存草稿、当前处理版本、任务冻结布局、手工建议；旧3×3不会自动改成4×2。手工导入不要求AI供应商或角色基准。

- **切帧**：选择原图格子、拖动裁切边界或输入坐标；内容原点独立。重新分析源图只更新建议，明确应用后才改变草稿。透明格保留供核对，可标记为有意空白帧。
- **动作分组**：物理行列与动作独立。默认全部有效格扫描成一个动作，可明确选择每行、每列，或选格加入／新建动作。每次加入创建独立帧实例，格子可复用。
- **对齐**：暂停选帧，拖动人物、方向键或输入偏移。多选施加相同增量；像素项目按逻辑像素编辑，处理时转换到输出像素。锚点建议需人工确认，“固定站位”先预览再明确应用，保留跳跃等有意位移。

实时画布是草稿预览；“验证处理”使用实际处理管线返回的帧查看输出像素。逻辑母版和输出帧各烘焙一次修正，采用不会再次叠加。保存只创建处理版本，返回候选后“确认检查并采用”；FPS、循环、顺序及逐帧时长跟随处理版本。

窄工作区右侧面板覆盖画布时，“保存修正并返回检查”固定在该面板底部；关闭面板后主操作返回编辑器底部。

## 结果恢复

启动时分开验证任务、方案、基准和容器。可核实的历史 `source:…` 本地导入编号先备份原JSON，再迁移为确定性合法编号，并保留原编号。异常记录保留在备份和诊断中，可读取部分继续显示；生成状态写入暂停，本地正式动作仍可编辑、导出。无法可靠枚举素材引用时保守暂停绘图素材垃圾回收，恢复完整读取后解除。

“任务读取”与“工程保存”是独立状态；读取失败不代表0任务。最近有效内容会保留，支持重试读取、查看素材和诊断。迁移、恢复、导入和保存修帧均不重新生图。
